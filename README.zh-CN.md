# NocoITAM

[English](README.MD) | 中文

NocoITAM 是面向 IT 团队的 IT 资产管理系统，基于 [NocoBase 3](https://www.nocobase.com) 构建。它把设备、配件、耗材、组件和软件授权放在同一本台账里，覆盖采购、分配、借用、维修、盘点到报废的全过程；为新员工准备设备、从离职员工手里收回资产；并与 Microsoft Intune 和 Jamf Pro 核对台账。它为团队配备了一组 AI：可以对话的资产管家，在业务现场读单据、帮你判断的 AI，以及审阅审批、跟进 MDM 差异的后台 Agent。每个 Agent 都只在它所服务的人的权限内工作，它建议的每一处修改都要等人确认。

## 快速开始

在自己电脑上运行 NocoITAM，只需要 Node.js 和 pnpm：数据存在一个 SQLite 文件里，除了 AI，所有功能都不需要任何账号或密钥。整个过程大约十分钟。

### 1. 安装工具

- **Node.js 24 或更高版本**。用 `node -v` 查看。
- **pnpm 10**。用 `npm install -g pnpm@10` 安装，或运行 `corepack enable`。
- **可选：一个大模型服务的 API Key**，资产管家和 AI 功能需要它，例如 DeepSeek、OpenAI、Claude、Gemini 或通义千问。应用运行起来后再添加（第 6 步）。

### 2. 获取代码

```bash
git clone https://github.com/nocobase/NocoITAM.git
cd NocoITAM
pnpm install
```

### 3. 生成配置

```bash
pnpm nocobase config init
```

这会生成配置文件 `config.yml`，其中 `secrets` 部分有一个自动生成的密钥，用来加密应用保存的模型密钥和 MDM 凭据。请保管好这个密钥：没有它，加密过的内容就无法读取。`config.yml` 不会提交到 Git。

第一次启动前先选好语言：中文用 `pnpm nocobase config set i18n.defaultLocale=zh-CN`（默认是英文）。它决定初始化写入的分类、地点、部门和业务指导用哪种语言，以及系统初始的币种和时区（中文为人民币和上海，其他为美元和纽约；之后都可以在**设置 → 通用**里修改）。

### 4. 启动应用

```bash
pnpm dev
```

第一次启动会创建并初始化数据库 `storage/itam.sqlite`。准备好后会打印一个 `Local:` 地址，通常是 `http://127.0.0.1:13000/main/`。打开这个地址；如果 13000 端口被占用，会自动换到下一个空闲端口，所以请以打印出来的地址为准。

### 5. 登录

用初始管理员登录：用户名 `nocobase`（或邮箱 `admin@nocobase.com`），密码 `admin123`。登录后可以在**设置 → 用户**里修改密码。系统不开放自助注册，其他账号都由管理员创建。

界面语言可以在右上角头像菜单里切换。

### 6. 上手

1. **用演示数据看看**。页面顶部的横幅会提示导入，也可以打开**设置 → 演示数据**，选择中文或英文导入（见下方[演示数据](#演示数据)）。
2. **添加团队成员**。在**设置 → 用户**里创建账号或发送邀请，并给每个人分配角色（见下方[角色](#角色)）。只有 IT 人员需要登录；员工是台账里的人员，没有账号。
3. **准备主数据**：在**主数据**下维护分类及其扩展字段、型号、供应商、地点、部门和入职配置。也可以用 CSV 导入现有台账。
4. **连接 Intune 或 Jamf Pro**（如果在用），在**设置 → MDM**（见[配置](#配置)）。
5. **使用 AI**。先在 **Agent 团队 → 模型**里添加一个模型服务和它的密钥（DeepSeek、OpenAI、Claude、Gemini、通义千问等都可以）。之后就可以在任意页面和资产管家对话；在 **Agent 团队 → 业务指导**里写下公司的规则（买什么、找谁买、设备多久更换、什么需要审批）；在 **Agent 团队 → Agent 工作**里开关后台 Agent。没有模型时，除 AI 外的功能都能正常使用。
6. **正式使用**。在**设置 → 演示数据**里清除演示数据，你自己的数据会保留。

| ---- | ------------------------------------------------ | ----------------------- | ---------------------- |
| 英文 | `daniel` (Daniel Brooks), `emily` (Emily Carter) | `ryanm` (Ryan Mitchell) | `markt` (Mark Taylor)  |

导入演示数据的管理员也会成为 IT 资产经理，并分到自己的审批、采购单、维修单、报废单和盘点任务。演示数据里的价格按人民币书写，导入时会换算成系统设置的币种。清除演示数据会把它连同演示账号和通知一起删除。

### 角色

账号在**设置 → 用户**里创建，每个账号可以有一个或多个角色；不开放自助注册。

| 角色        | 能做什么                                           |
| ----------- | -------------------------------------------------- |
| 管理员      | 配置 ITAM、它的 Agent 和各项集成，查看全部内容     |
| IT 资产经理 | 台账里的所有工作，包括审批采购单和报废单、删除记录 |
| IT 支持     | 和资产经理一样的日常工作，但不能审批和删除         |

每个角色能做什么，可以在**设置 → 权限集**里调整。

### 常见问题

| 遇到的情况                              | 怎么办                                                                                                                     |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `pnpm install` 拒绝运行或报 engine 错误 | 使用 Node.js 24 或更高版本和 pnpm 10（第 1 步）。                                                                          |
| 页面打不开                              | 使用 `pnpm dev` 打印的 `Local:` 地址，包括 `/main/`。同一个目录只能运行一个 `pnpm dev`，先停掉另一个。                     |
| 看不到 AI 按钮，或资产管家不可用        | 还没有连接模型。在 **Agent 团队 → 模型**里添加模型服务和密钥。                                                             |
| 单据读不出来                            | AI 读的是文字：Excel、CSV、Word 和文字版 PDF。照片和扫描版 PDF 没有文字可读，请手动输入或粘贴内容。                        |
| 忘记管理员密码                          | 让另一位管理员在**设置 → 用户**里重置。本地环境也可以按下面的方法重新开始，并在 `config.yml` 里设置新密码。                |
| 保存的密钥或 MDM 连接失效了             | `config.yml` 丢失或被重新生成。恢复备份的 `config.yml`，或者重新填写密钥、重新连接平台。                                   |
| 想用空数据库重新开始                    | 停掉 `pnpm dev`，删除 `storage/itam.sqlite`、`storage/objects/` 和 `storage/ai-files/`，再重新启动。这会删除所有本地数据。 |
| 想更新到最新版本                        | `git pull`，然后 `pnpm install` 和 `pnpm dev`。数据库变更会在启动时自动执行；如果数据重要，请先备份 `storage/`。           |

## AI 功能

ITAM 的所有 AI 都基于 Agents 插件，使用应用配置的模型服务运行（见[配置](#配置)）。

**资产管家**。任意页面都能打开对话面板，历史对话会保留。资产管家根据当前用户能看到的数据回答，能读取附件，也知道用户正在看哪条记录。需要改动时，它会给出一个计划（分配设备、发起采购、交接离职员工的记录），由用户在卡片上逐步确认。它以这个用户的身份操作，从不超出其权限。

**在业务现场的 AI**。带着单据或需要判断的环节，AI 直接在原地完成，填好表单让人核对后保存：

| 在哪里                     | AI 做什么                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 新建采购单                 | 从粘贴的文字或上传的申请、报价单、发票填好采购单，明细对上台账里的型号和软件产品       |
| 草稿采购单的明细           | **解析单据**：把报价单、发票或送货单里的明细加到订单                                   |
| 新建型号、软件产品或制造商 | 填好规格和支持信息；连接了能联网搜索的模型时会上网查                                   |
| 收货                       | 对照订单明细读送货单：数量、序列号、保修期，以及少收、多收了什么                       |
| 新员工的设备               | 入职负责人请求时，从库存里挑选设备并说明理由                                           |
| 新建维修                   | 判断故障类型、维修方式，以及修还是换；建议更换时可以直接改为创建报废单                 |
| 维修报价                   | 读供应商报价，对比设备净值、使用年限和维修记录，给出建议维修、建议直接更换或先核对报价 |
| 完成维修                   | 读维修报告或发票：维修结果、费用和做了什么；单据写的不是这台设备时会警告               |
| 新建报废                   | 填好报废原因、方式和数据清除，并指出暂时不该报废的设备（还在保修、净值高、租赁的）     |
| 执行报废                   | 读回收或数据销毁证明：接收方、日期、金额和清除方式，并列出证明上缺了哪些设备           |
| **MDM 核对**               | 整理一批与平台信息不一致的设备                                                         |

单据可以粘贴、拖入或上传，一次可以传多个；上传的文件会保存在这条记录的附件里。

**Agent 工作**。两个 Agent 在后台工作，各自由事件触发，可以在 **Agent 团队 → Agent 工作**里开关：

| Agent        | 触发时机                                                | 产出                                                                                                   |
| ------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 审批助手     | 采购单或报废单提交审批                                  | 给审批人的审阅：要什么、花多少钱、库存或闲置设备能否顶上、以前同类申请怎么批的、建议和拟好的审批意见   |
| MDM 差异跟进 | 每次 MDM 同步：每晚的自动同步，以及设置里的**立即同步** | 针对新差异的处理方案：平台用户和台账使用人不一致的设备交给它的负责人，台账里没有的平台记录交给资产经理 |

它们的建议会出现在相关人员的**收件箱**和对应记录上，逐条接受或忽略；在人做决定之前，什么都不会改动。

**按你的方式工作**。每个 Agent 遵循的方法是一项技能，在 **Agent 团队 → 技能**里编辑（初始技能在 `ai/skills/`）；公司自己的规则写在 **Agent 团队 → 业务指导**。Agent、它们使用的模型和 token 用量分别在 **Agent 团队 → Agent**、**模型**和**用量**里。AI 自己撰写的内容使用**设置 → 通用**里的 **AI 工作语言**（中文或英文）；资产管家用提问的语言回答。

## 其他功能

- **台账**。五类资产，各有列表、看板和详情页：设备逐台管理，带资产编号、序列号、使用人、地点、保修和折旧；配件、耗材和组件按数量管理，带最低库存水位；软件授权包括买断授权和订阅，带席位、密钥、续订日期和合规状态。分类定义扩展字段，型号会把它们作为新设备的默认值。
- **全生命周期**。设备可以分配、借出（带归还日期）、预留、调拨和归还；库存可以发放、收回，并带原因调整数量；授权席位可以分配和回收。每条记录都有历史，支持评论、@ 提及和附件。
- **采购**。采购单经发起、指定审批人审批、下单和收货，序列号可以粘贴或用扫码枪录入。
- **维修**。维修单有负责人，负责记录供应商报价、决定继续维修还是改为报废、完成维修；维修结束可以是已修复、无法修复、已更换整机、已取消或改为报废。
- **盘点和报废**。盘点逐台清点，每处差异都要处理；报废先审批后执行，记录接收方、金额和数据清除情况。
- **入职和离职**。每个部门、每个岗位都有入职配置。新员工卡片显示他会领到的设备、库存和授权，还需要采购的东西从待办里直接发起采购单。离职员工的资产分批收回，他负责的记录交接给别人，最后一天自动停用登录。
- **MDM**。每晚读取 Microsoft Intune 和 Jamf Pro，按序列号匹配台账。**MDM 核对**列出不一致的地方（使用人或状态不同、设备长期失联、平台有而台账没有、平台不管理的设备），可以关联、补登记、豁免或忽略；每台设备的详情页也会显示平台上报的信息。
- **待办**。先是风险（保修和订阅即将到期、授权超量使用、库存低于最低水位、设备长期未盘点），然后是团队的工作看板：待审批、人员变动、借出逾期、采购中、维修中、报废中、MDM 核对、盘点中，可以只看自己的或看全部。
- **收件箱**。等待当前用户处理的 AI 建议，以及通知：审批、审批结果、@ 提及、回复、盘点和借出逾期。
- **报表**。总览、资产台账、分布、成本与折旧、人均 IT 成本、保修与到期、软件合规、维修、盘点结果和变动；每张表都能导出 CSV。
- **全局搜索**。⌘K / Ctrl+K 搜索所有类型的记录，也可以把问题交给资产管家。
- **导入导出**。台账和主数据支持 CSV 导入导出。
- **语言**。界面、演示数据和 AI 工作语言支持中文和英文。

## 配置

`config.yml` 保存密钥，不提交到 Git；`config.example.yml` 说明了所有配置项。用 `pnpm nocobase config set key=value` 修改配置。

**语言**。`i18n.defaultLocale`（`en-US` 或 `zh-CN`，也可以用 `APP_DEFAULT_LOCALE`）是应用启动时的语言，也决定创建数据库时初始数据用哪种语言，以及初始的币种和时区。请在第一次启动前设置。

**AI**。在 **Agent 团队 → 模型**里添加模型服务和密钥，或者在 `config.yml` 的 `ai.llmServices` 下声明，密钥直接写成值（不会展开 `${NAME}` 占位符；`pnpm nocobase config set --from-env ai.llmServices.deepseek.options.apiKey=DEEPSEEK_API_KEY` 可以从环境变量读取）：

```yaml
ai:
  llmServices:
    deepseek:
      title: DeepSeek
      provider: deepseek
      enabledModels:
        - label: DeepSeek V4.1 Flash
          value: deepseek-flash
      enabled: true
      sort: 10
      options:
        apiKey: <key>
```

启动时，配置里声明了、但 **Agent 团队 → 模型**里还没有的服务会自动创建到那个页面，之后由页面管理。资产管家按 `sort` 顺序使用这些服务，第一个是默认服务。新建型号或软件产品时上网查资料，需要一个能联网搜索的模型服务。

**通知**。站内收件箱需要 `in-app` 通道（`notification.channels.in-app: { provider: in-app }`，`config.example.yml` 里已经有）。

**MDM**。在**设置 → MDM**里连接 Intune 和 Jamf Pro，或者在 `config.yml` 的 `deviceSync` 下配置（`INTUNE_TENANT_ID`、`INTUNE_CLIENT_ID`、`INTUNE_CLIENT_SECRET`、`JAMF_URL`、`JAMF_CLIENT_ID`、`JAMF_CLIENT_SECRET`），配置文件里的优先，页面上会显示为只读。Intune 需要一个 Entra ID 应用注册，并授予 Microsoft Graph 应用权限 `DeviceManagementManagedDevices.Read.All`；Jamf Pro 需要 10.49 或更高版本，以及一个角色只含 Read Computers 和 Read Mobile Devices 的 API 客户端。

**定时任务**。每晚自动运行四个任务，不需要配置：01:30 MDM 同步，01:50 更新在职状态（新员工在入职当天生效，离职员工在最后一天离职），02:00 日常维护（续订、过期预留、借出逾期），以及每月 1 日 03:00 计提折旧。每次运行记录在**设置 → 定时任务**；时区、各项阈值、编号规则和入职准备天数在**设置 → 通用**。

**访问地址**。`APP_BASE_PATH` 是挂载路径（默认 `/main`），`APP_PUBLIC_ORIGIN` 是不含路径的公开地址。部署时必须设置公开地址，否则浏览器的写操作会被拒绝（`403`）。

**数据库**。默认使用 SQLite，文件是 `storage/itam.sqlite`；迁移和初始化数据在启动时执行。要用 PostgreSQL，添加 `@nocobase/db-postgres` 并运行 `pnpm nocobase config init --dialect postgres --force`。

## 基于 NocoBase 3

NocoBase 3 是一个用编程 Agent 构建业务软件的应用底座。它的 App Foundation 提供每个业务应用都需要的基础设施，应用不必重复建设。NocoITAM 是一个 NocoBase Solution：由 NocoBase 应用模板生成的完整应用，在底座之上有自己的数据模型、服务、API 和页面。

| 来自 NocoBase 3              | NocoITAM 用它做什么                                                           |
| ---------------------------- | ----------------------------------------------------------------------------- |
| 应用服务器、数据库层和 CLI   | 服务端、迁移和初始化数据、配置、构建和部署                                    |
| 应用模板和 UI 组件库         | 布局、路由、主题、登录页，以及构成每个页面的组件                              |
| 认证、用户和 API Key         | 登录、IT 团队的账号和个人 API Key                                             |
| 权限（权限集、记录访问规则） | 三个角色、记录和字段权限、页面授权，以及权限集设置                            |
| Agents 插件                  | 资产管家、对话、技能、模型服务、用量，以及 ITAM 提供给 Agent 的命令           |
| 通知插件                     | 站内收件箱                                                                    |
| 生命周期库                   | 设备、采购单、维修单、盘点和报废单的状态与流转，以及**设置 → 流程**里的流程图 |
| 定时任务                     | 每晚的 MDM 同步、在职状态更新、日常维护和每月折旧                             |
| 文件和多语言插件             | 附件、型号图片和 AI 读取的单据，中英文界面                                    |
| Database Explorer            | 只读浏览应用的数据表                                                          |

## 部署

为服务器构建一个安装包。它包含代码和生产依赖，不包含配置、数据库和上传的文件：

```bash
pnpm build --target linux-x64 --tar   # 生成 storage/exports/dist.tar.gz
```

- **使用 NocoBase app-installer（推荐）**。服务器需要 Node.js 24 和全局安装的 pm2。安装程序会解压安装包、生成 `config.yml`、执行迁移，并用 pm2 运行应用；升级时会先备份 SQLite 数据库，新版本启动失败时自动回滚。

  ```bash
  npx @nocobase/app-installer@beta install /srv/nocobase/itam --archive dist.tar.gz --origin https://itam.example.com --base-path /itam
  npx @nocobase/app-installer@beta upgrade --dir /srv/nocobase/itam --archive dist.tar.gz
  ```

- **手动部署**。解压安装包，在 `dist/` 里运行 `pnpm nocobase config init` 和 `pnpm nocobase config check`，再用服务管理器运行 `node ./dist/server/standalone.js`；更新时保留 `dist/` 旁边的 `config.yml` 和 `storage/`。
- **Docker**。用 `docker build -t nocoitam .` 构建，把 `config.yml` 以只读方式挂载到 `/app/config.yml`，把一个卷挂载到 `/app/storage`，用 `-e APP_BASE_PATH=/itam` 指定路径。
- **NocoBase Studio**。发版标签（`v<版本号>`，打在 `Release <版本号>` 提交上）会触发 `.github/workflows/deploy-studio.yml`：检查并构建一次，然后部署到每个已配置 Studio 上的应用 `itam`。

如果要把前端静态文件放到 CDN，用 `CDN_BASE_URL=https://cdn.example.com/itam/v1/ pnpm build` 构建，把 `dist/client/` 按原路径上传到 CDN 并允许应用域名的跨域访问，同时服务器上也要保留 `dist/client/`，HTML 仍由服务器提供。

放在反向代理后面时，要保留原始的主机名和协议，并转发 WebSocket 升级请求。部署后填好 AI 密钥，检查 `<挂载路径>/api/healthz`。升级前请备份数据库和 `storage/`。

## 开发

`AGENTS.md` 是开发指南，适用于 Claude Code 或其他编程 Agent；`.agents/rules/` 是它索引的各领域规则，`docs/IMPLEMENTATION_PLAN.md` 记录已做出的决策。常用命令：

| 命令                              | 作用                                           |
| --------------------------------- | ---------------------------------------------- |
| `pnpm dev`                        | 启动服务端和前端，支持热更新                   |
| `pnpm build`                      | 构建到 `dist/`                                 |
| `pnpm start`                      | 运行构建产物                                   |
| `pnpm test`                       | 运行 `tests/` 里的测试                         |
| `pnpm typecheck`                  | 对前端和服务端做类型检查                       |
| `pnpm lint`                       | 代码检查                                       |
| `pnpm check`                      | 以上全部，再加一次构建                         |
| `pnpm nocobase db apply`          | 不重启，直接执行待执行的迁移                   |
| `pnpm --silent data:reset --demo` | 清空 ITAM 数据，重新初始化并在本地生成演示数据 |
| `pnpm nocobase --help`            | 列出其他所有命令                               |
